# Data sources and offline mode

Kinroot runs fully offline with no accounts or keys. Real public data is optional: small subsets are downloaded
into the git-ignored `data/` folder by the scripts below and are never committed. Everything the demo needs
offline is synthetic, generated by code or bundled as small fixtures, and labelled "Sample data" in the product.

| Source | What we use | Access | Licence | Where it lands | Offline fallback |
|---|---|---|---|---|---|
| UK Companies House: PSC snapshot | One ~80 MB part of the daily "people with significant control" snapshot → 300 company structures with corporate PSCs + 20,000 individual PSC records | Free bulk download, **no key** | Open Government Licence v3.0 | `data/companies_house/` (used automatically when present) | Bundled synthetic UK structure for the Northgate seed; synthetic people for matcher training |
| UK Companies House: REST API | Company profile, officers, PSC per company | Free, **needs an API key** (returns 401 without one) | OGL v3.0 | – | Not used: no REST client is included (the `COMPANIES_HOUSE_SOURCE` / `COMPANIES_HOUSE_API_KEY` settings are reserved for one) |
| OpenSanctions | AU, UK and UN sanctions lists; AU federal/NSW and UK parliament PEPs (FollowTheMoney JSON) | Free download, no key | **CC BY-NC 4.0**: free for non-commercial use with attribution; commercial use needs a licence | `data/opensanctions/` | Bundled fictional sample list (`SAMPLE-SAN-*`, `SAMPLE-PEP-*`) |
| ABN Lookup (Australian Business Register) | ABN/ACN entity details | Free web services but **needs a registered GUID** (without one the JSON service answers "The GUID entered is not recognised") | ABR terms | `data/abn/` (only with a GUID) | **Mock adapter** over a synthetic AU registry. This is the only AU adapter: no live ABN Lookup client is included (`ABN_SOURCE` is reserved for one) |

Reachability was checked during development: the PSC snapshot page and its parts download without
credentials; the Companies House REST API returns `401` without a key; OpenSanctions dataset indexes and files
download without credentials; the ABN Lookup JSON endpoint responds but refuses requests without a GUID.

## Downloaders (`scripts/`)

All use the Python standard library, prefer IPv4 (some networks drop IPv6 silently) and refuse to exceed a size
cap. Run them one at a time.

```bash
make data                      # both downloads below (~120 MB transferred, ~50 MB kept)
backend/.venv/bin/python scripts/fetch_opensanctions.py            # ~40 MB, 7 datasets
backend/.venv/bin/python scripts/fetch_companies_house.py          # downloads 1 part (~80 MB), keeps ~9 MB
ABN_LOOKUP_GUID=… backend/.venv/bin/python scripts/fetch_abn.py 53004085616   # optional
```

### OpenSanctions subset (`scripts/fetch_opensanctions.py`)
Default datasets (FollowTheMoney `entities.ftm.json`, one entity per line; `--format csv` for `targets.simple.csv`):

| Dataset | Kind | Approx. size |
|---|---|---|
| `au_dfat_sanctions`: Australian Sanctions Consolidated List | sanctions | 10 MB |
| `gb_fcdo_sanctions`: UK sanctions list | sanctions | 23 MB |
| `un_sc_sanctions`: UN Security Council consolidated list | sanctions | 3 MB |
| `au_parliament`, `au_nsw_parliament` | PEP | < 1 MB |
| `gb_commons`, `gb_lords` | PEP | 3 MB |

Output: `data/opensanctions/<dataset>/entities.ftm.json`, its `index.json`, and `data/opensanctions/manifest.json`
(`{dataset: {version, kind, file, sha1, entities, licence}}`), verified against the publisher's SHA-1. The
screening loader reads the manifest when `SANCTIONS_SOURCE=opensanctions`. The full `default` collection is
several GB and is deliberately not used.

### Companies House PSC sample (`scripts/fetch_companies_house.py`)
Finds the current `psc-snapshot-YYYY-MM-DD_<n>of<N>.zip` on the snapshot page, downloads part 1 (about 80 MB),
streams it once and writes:

- `psc_structures.jsonl`: 300 companies that have at least one **corporate** PSC, with all their PSC statements
  (`{companyNumber, pscs: [...]}`, raw Companies House JSON).
- `psc_individuals.jsonl`: 20,000 individual PSC records reduced to name parts, birth month/year, nationality,
  country of residence, locality and postcode.
- `manifest.json`: source file, counts and SHA-256 of both outputs. The zip is deleted afterwards (`--keep-zip`).

What it is used for:
1. **Registry import mapping** (`/registry/search?source=uk_ch`): PSC `natures_of_control` bands map to ownership
   edges (`ownership-of-shares-25-to-50-percent` → `pct` lower bound 25, band kept in `sourceRef`) and control
   edges (`right-to-appoint-and-remove-directors`, `significant-influence-or-control`).
2. **Entity-resolution training pairs**: real name/birth-date/locality distributions, perturbed with typos,
   initials, transliterations, swapped name order, missing fields and date slips to build labelled matching and
   non-matching pairs (ADR 0003). Only derived features and aggregate metrics leave `data/`.

Limits, stated plainly: the snapshot is split by part, so a corporate PSC's own owners usually live in another
part. The sample therefore gives real **one-layer** structures; deep multi-layer chains (trusts over companies over
offshore holdings, cycles) come from the synthetic seed. PSC data names real people: it stays local, is never
committed, and is not shown in screenshots.

### ABN Lookup (`scripts/fetch_abn.py`)
Without `ABN_LOOKUP_GUID` it prints a note and exits. With a GUID it saves raw JSON for the given ABNs to
`data/abn/` so the mock adapter's mapping can be checked against real responses.

## Bundled synthetic data (committed, offline)

| Fixture | Contents |
|---|---|
| `backend/screening/data/sample_lists.json` | 60 fictional sanctions and PEP entries (`SAMPLE-SAN-*`, `SAMPLE-PEP-*`) including the seed's near-matches; FollowTheMoney-shaped |
| `backend/clients/data/au_registry_mock.json` | Fictional AU companies (ACN/ABN with valid check digits), trusts, partnerships, officers and addresses behind the mock ABN adapter |
| `backend/clients/data/uk_structure_sample.json` | Fictional UK PSC-shaped structure for Northgate when the Companies House sample is absent |
| `backend/resolution/data/` | Name lists and generator settings (seeded RNG) for synthetic people and companies. Matcher training mixes them with perturbed Companies House PSC records when `data/companies_house/` exists and uses them alone otherwise |
| `backend/risk/data/` | Generator settings for labelled synthetic client outcomes (rules + graph features, seeded) for the challenger |
| `backend/artifacts/models/` | Small trained model files (LightGBM text dumps, calibrators, thresholds JSON) so the demo scores without `make train` |

All generators use fixed seeds: the same commit (and, for the matcher, the same Companies House sample) produces
the same data, models and eval numbers. The committed matcher was trained with the sample present, so `make train`
without `make data` gives a synthetic-only matcher with different numbers.

## Data handling rules

- `data/`, `mlruns/` and `*.db` are git-ignored. Never commit downloaded or licensed data.
- Personal data from public registers stays on the machine; screenshots and docs use the synthetic seed only.
- Record retention: the demo applies the firm's retention setting (7 years AU, 5 years UK) to seeded records;
  disposal is a dry run unless explicitly confirmed.
- Data residency: the default deployment note is AU-hosted storage for AU firms; nothing leaves the machine in
  offline mode. Cloud language-model calls (optional) send only graph facts needed for the answer, never documents.
- Attribution: every screening list version returned by `GET /screening/lists` carries its licence and attribution
  text ("Sanctions and PEP data: OpenSanctions (opensanctions.org), licensed under CC BY-NC 4.0" for loaded
  OpenSanctions lists; a "Sample data" note for the bundled lists), and Settings → Screening lists shows each list's
  source and version. The Companies House notice ("Contains public sector information licensed under the Open
  Government Licence v3.0") applies whenever the PSC sample is used. A deployment that loads either source should
  show both notices to users.
